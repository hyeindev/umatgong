## 1. 구조 원칙

**지도가 곧 홈이다.** 앱을 켜면 바로 지도다. 클럽 선택도, 로딩 화면도, 중간 단계도
없다. 가입한 모든 클럽의 핀이 처음부터 한 지도에 겹쳐 뜬다.

**클럽은 색으로 구분한다.** 클럽을 고르는 게 아니라 여러 클럽이 동시에 보이고
색으로 구분된다.

**깊이를 얕게 유지한다.** 지도 → 핀 탭 → 자세히 보기가 최대 깊이다.

**필터는 사람이 생각하는 단위로.** "500m"가 아니라 "걸어서 10분".

---

## 2. 전체 구조

```
지도 (홈, 항상 여기서 시작)
├── 핀 탭 → 미니 카드 (지도 위 겹침)
│            └── 자세히 보기 → 장소 상세
├── 「내 근처 맛집」 ─┐
│                    ├→ 리스트 시트 (같은 화면, 상태만 다름)
├── 검색 아이콘 ─────┘     └── 항목 탭 → 장소 상세
├── 기록 배지 → 기록하기 (새 사진 대기 시에만 노출)
└── 프로필 → 내 지도 / 클럽 / 설정
```

하단 탭바를 두지 않는다. 지도가 화면 전체를 쓰고, 진입점은 지도 위 플로팅 버튼.

「내 근처 맛집」과 검색은 **같은 리스트 시트의 두 상태**다. 검색어가 걸려 있느냐의
차이일 뿐이며 필터 바와 결과 레이아웃은 동일하다. 화면을 분리하지 않는다.

## 4. 화면 상세

### 4.1 지도 (홈)

앱의 전부에 가까운 화면. 실행 즉시 진입.

**기본 상태**
- 지도 전체 화면, 현재 위치로 자동 이동 (반경 약 1km)
- 가입한 **모든 클럽의 핀**이 동시에 표시
- 내 위치는 빨간 위치 핀

**핀 규칙**

| 요소 | 규칙 |
|---|---|
| 색상 | 클럽별 고유 색. 생성 시 자동 배정, 변경 가능 |
| 형태 | 평가 3단계 — 「또 갈래」 채운 핀 / 「괜찮」 테두리 핀 / 「별로」 흐린 핀 |
| 내 위치 | 빨간 위치 핀. **클럽 팔레트에서 빨강 계열 제외** |
| 겹침 | 근접 핀은 클러스터로 묶고 숫자 표시 |
| 여러 클럽 중복 | 분할 색 핀 또는 다중 링 |

> **색만으로 구분하면 색각 이상 사용자가 클럽을 구분할 수 없다.**
> 클럽은 색, 평가는 형태로 축을 나눠 최소한의 접근성을 확보한다.

**오버레이**
- 상단 좌측: 클럽 필터 칩 (2개 이상일 때만 노출, 각 칩에 클럽 색 점)
- 상단 우측: 검색 아이콘, 프로필
- 우하단 (아래→위): 「내 근처 맛집」(주 버튼) / 현재 위치 / 기록 배지(대기 시에만)

**빈 상태**
"아직 기록이 없어요. 사진첩에서 찾아볼까요?" + 온보딩 재진입

**성능**
화면에 보이는 영역의 핀만 조회. 지도 이동이 멈춘 뒤 조회(디바운스 300ms).

---

### 4.2 미니 카드

핀을 탭하면 지도 위에 겹쳐 뜬다. **화면 전환이 아니다.**

**담을 것**
썸네일 / 가게명 / 클럽 색 점 + 클럽명 / 방문 친구 아바타 스택 /
대표 평가("3명 중 3명이 또 갈래") / 거리·소요시간 / 「자세히 보기」

**동작**
- 좌우 스와이프 → 근처 다른 핀으로 이동, 지도도 함께 움직임
- 지도 빈 곳 탭 → 닫힘
- 위로 드래그 → 장소 상세

---

### 4.3 내 근처 맛집 / 검색 (바텀시트)

**필터를 거치지 않고 바로 목록이 뜬다.** 기본값은 "걸어서 10분, 전체 클럽, 또 갈래만".

**시트 3단계**

| 단계 | 상태 |
|---|---|
| 접힘 | 필터 바 + 첫 항목 1개 |
| 중간 | 지도 40% + 리스트 60% (기본 진입) |
| 펼침 | 리스트 전체 화면 |

**필터 바** (시트 최상단 고정, 가로 스크롤)

```
[파스타 ✕]                        ← 검색어 (검색 진입 시에만)
[걸어서] [버스] [자차]             ← 이동수단, 단일 선택
[5분] [10분] [30분]  [또 갈래만]   ← 시간, 단일 선택 + 토글
```

선택 즉시 리스트와 지도가 갱신된다. **적용 버튼 없음.**

> **소요시간 계산 방식**
> 카카오 경로 API로 실제 소요시간을 계산하되, **매 항목마다 호출하면 비용이
> 감당되지 않는다.** 2단계로 처리한다.
> 1. **반경 1차 필터링** — 도보 분당 67m, 버스 250m, 자차 400m를 직선거리 근사값으로 사용
> 2. **화면에 보이는 항목만 실제 조회** — 리스트에 렌더링되는 5~10개만 호출.
>    스크롤로 새 항목이 나타날 때 추가 조회
>
> 결과는 좌표 쌍 기준으로 캐싱해 같은 세션에서 재호출하지 않는다.

**리스트 항목**
썸네일 / 가게명 + 카테고리 / 클럽 색 점 / 소요시간("걸어서 7분") /
친구 아바타 + 평가 요약 / 최근 방문일

**정렬**
기본 가까운 순. 「또 갈래 많은 순」, 「최근 방문 순」으로 변경 가능.

**검색 진입**
검색 아이콘을 누르면 **빈 검색창이 아니라 추천 태그 칩**이 먼저 뜬다.

```
[파스타 12] [고기 9] [카페 8] [국밥 6] [일식 5]
```

내 데이터에서 많이 나온 태그를 빈도순으로, 개수와 함께. 탭하면 즉시 결과.
검색 편의인 동시에 수집 만족감을 자극하는 자리다.

검색 대상 우선순위: 사진 자동 태그 → 가게 업종 태그 → 가게명 → 메모

**태그를 결과 카드에 나열하지 않는다.** 태그는 인덱스일 뿐이며 틀린 태그가
눈에 띄면 신뢰가 깎인다. 사진과 가게명만 보여주고 사용자가 판단하게 둔다.

**빈 결과**
"걸어서 10분 안에는 없어요" + "30분으로 넓혀보기". 빈 화면만 보여주지 않는다.

### 4.4 장소 상세

**상단** 사진 갤러리 — 친구들이 찍은 사진 가로 스크롤, 촬영자 아바타 표시

**정보** 가게명, 카테고리, 주소, 클럽 색 점

**핵심 신호** "내 친구 4명 중 4명이 또 갈래" — 이 앱이 주는 확신이므로 가장 강조

**방문 기록** 시간순. 방문자 아바타, 날짜, 평가, 한 줄 메모, 사진

**하단 고정** 「길찾기」(외부 지도앱) · 「가고싶다」

**내 기록이 있으면** 상단에 "나도 갔던 곳" + 평가 수정 진입점

---

### 4.5 기록하기

**구성**
- 상단: "새로 찾은 사진 3장" + 남은 개수
- 중앙: 음식 사진. 같은 끼니(좌표·시각 근접)는 묶어서 표시
- 하단 상단부: 자동 추정 후보 최대 4개 + 「여기 없어요」
- 하단: 평가 3단계 버튼

**후보 정렬 순서**
1. 클럽 친구가 이미 기록한 가게
2. 내가 전에 기록한 가게
3. 음식점 카테고리 (거리순)

> 친구가 갔던 곳을 최상단에 두면 적중률이 크게 오른다. 쓸수록 정확해지는 구조.

**동작**
후보 탭 → 평가 탭 → 자동으로 다음 카드 / 좌측 스와이프 건너뛰기 /
「나중에」로 복귀. **목표는 한 장당 1~2초.**

**한 손 조작**
후보 목록과 평가 버튼은 모두 **화면 하단 절반**에 배치한다.

---

### 4.6 위치 지정

「여기 없어요」를 눌렀을 때, 또는 좌표가 없는 사진.

**4개 경로**
검색 / 주변 후보 목록 / **「지금 내 위치로 등록」** / 지도에서 직접 찍기

**직접 입력**
넷으로 안 되면 가게명을 직접 입력. `source=USER`로 저장되며
**해당 클럽 안에서만** 후보로 노출된다. 다음에 같은 좌표에서 찍으면 후보로 뜨고
클럽 친구에게도 뜬다. 쓸수록 우리 클럽만의 지도 데이터가 쌓인다.

---

### 4.7 온보딩

**① 권한 요청**
사진첩은 가장 민감한 데이터다. **무엇을 왜 보는지 명확히 전달하는 것이 목표.**
최근 1년 음식 사진만 찾는다는 것, 분석은 기기 안에서 이뤄진다는 것, 언제든 취소
가능하다는 것. 「사진 몇 장만 골라서 시작」을 기본 강조, 「전체에서 찾기」는 부가 선택지.

**② 스캔 진행**
진행률 + 실시간 발견 개수. 완료 시 "38곳을 찾았어요".

**③ 카드 확인**
4.5와 동일 구조. 개수가 많으므로 속도가 더 중요.

**좌표 없는 사진은 온보딩에 노출하지 않는다.** "위치 미정" 묶음으로 분리.
첫 3분에 붙잡으면 이탈한다.

**완료 직후** 바로 지도로 진입. 방금 만든 핀들이 뿌려진 것을 보여주는 것이
온보딩의 마지막 장면이다.

---

### 4.8 클럽

클럽 목록(색, 이름, 멤버 수, 기록 수) / 멤버 아바타와 각자 기록 수 /
「초대 링크 복사」 / 정원 표시("8명 중 5명") / 클럽 색 변경

정원 초과 시 **기존 멤버는 그대로, 초대만 차단**됨을 명확히 안내.

---

### 4.9 내 지도

수집의 만족감을 담당한다.
내 핀 전체 / 통계 요약(방문한 곳, 이번 달 신규, 지역 수) / 지역별 정복도 /
방문 목록 뷰 전환

---

### 4.10 설정

계정, 사진첩 권한, 기본 이동수단·시간, 알림, 공개 범위 기본값,
클럽 탈퇴, 회원 탈퇴 및 데이터 삭제

## 6. 카카오 API 사용 방침

국내 한정 서비스이므로 **카카오맵으로 확정.**
결정적 이유는 좌표 기준 반경 장소 검색이다. 네이버 Maps에는 해당 기능이 없고,
좌표계도 달라 변환이 필요하다.

| 용도 | API |
|---|---|
| 지도 표시 | 지도 SDK (웹은 JS SDK) |
| 좌표 → 주변 음식점 | 카테고리 장소 검색 (`FD6`, `CE7`) |
| 가게명 검색 | 키워드 장소 검색 |
| 좌표 → 주소 | 좌표-주소 변환 |
| 소요시간 | 도보 / 대중교통 / 자동차 경로 조회 |

**쿼터 주의**
- 개발자 계정의 **첫 번째 활성화 앱에만 무료 쿼터**가 제공된다. 우맛공을 첫 앱으로 등록할 것
- 초기에는 비즈월렛을 연결하지 않는다. 초과 시 자동 과금 대신 에러가 나게 두고,
  실사용이 늘면 그때 붙인다

**호출을 줄이는 3가지**
1. `places` 캐싱 — 같은 가게는 한 번만 호출
2. 화면 영역 조회 + 디바운스
3. 경로 조회는 화면에 보이는 항목만 (4.3 참조)

## 7. 웹 / 네이티브 차이

하나의 코드베이스로 iOS · Android · 웹을 빌드하지만 역할이 다르다.

| 기능 | 네이티브 | 웹 |
|---|---|---|
| 사진첩 자동 스캔 | 지원 | **미지원** |
| 온보딩 대량 스캔 | 지원 | **미지원** |
| 지도 조회 | 지원 | 지원 |
| 내 근처 맛집 | 지원 | 지원 |
| 기록하기 | 자동 카드 | 수동 업로드 |
| 클럽 초대 링크 열람 | 지원 | 지원 |

브라우저에는 사진 라이브러리 API가 없다. 파일 선택 다이얼로그로 사용자가 직접
고르는 것만 가능하다.

**웹은 유입과 열람, 네이티브는 기록.** 웹에서 사진첩 기능이 없는 것은 결함이 아니라
설계다. 기획서 C-06(웹 링크로 지도 공유, 미설치자 열람)이 웹의 존재 이유다.

웹에서 네이티브 전용 기능에 접근하면 **에러를 띄우지 말고 앱 설치를 안내**한다.
